# راهنمای نسخهٔ محلی Casa Italy

این نسخه روی لپ‌تاپ اجرا می‌شود. هاست و دیتابیس هاست در این مرحله تغییری نکرده‌اند. انتشار بعدی فقط با تأیید کاربر و مرحله‌به‌مرحله انجام می‌شود.

## آدرس‌ها

- منوی دیجیتال: http://localhost:3000/
- لندینگ: http://localhost:3000/landing
- ثبت و پیگیری رزرو: http://localhost:3000/reservations
- مدیریت: http://localhost:3000/admin
- ورود مدیر: http://localhost:3000/admin/login

نام کاربری و گذرواژهٔ تولیدشده در `tmp/local-admin.txt` هستند. این فایل و `.env.local` در Git نادیده گرفته می‌شوند. گذرواژهٔ مشترک یا پیش‌فرض در سورس وجود ندارد. حساب و گذرواژه را می‌توان از بخش حساب‌های پنل تغییر داد؛ تغییر حساب، نشست‌های قبلی آن را بی‌اعتبار می‌کند.

## راه‌اندازی از ابتدا

Node.js 24، pnpm 10.34.5 و Docker Desktop لازم‌اند. از ریشهٔ پروژه:

```powershell
pnpm install --frozen-lockfile
pnpm local:setup
pnpm db:up
pnpm db:migrate
pnpm db:seed
pnpm admin:create
pnpm dev
```

`local:setup` فایل محیط موجود را بازنویسی نمی‌کند. `admin:create` نیز حساب موجود را بازنویسی نمی‌کند. ساخت حساب با گذرواژهٔ دلخواه از طریق متغیر محیطی `ADMIN_PASSWORD` و نام دلخواه از طریق `ADMIN_USERNAME` ممکن است؛ اطلاعات محرمانه را در تاریخچهٔ فرمان یا Git قرار ندهید.

PostgreSQL اصلی محلی در سرویس `db`، روی `127.0.0.1:55432` با نام `casa_local` و کاربر `casa` قرار دارد. رمز تصادفی در `.env.local` است. volume نام‌دار `casa-italy_casa_db` داده را بعد از restart نگه می‌دارد. پروژه به دیتابیس‌های Docker پروژه‌های دیگر متصل نیست.

برای مشاهدهٔ مستقیم دیتابیس در ترمینال:

```powershell
docker compose --env-file .env.local exec db psql -U casa -d casa_local
```

## امکانات پنل و منو

- ایجاد، ویرایش، ترتیب، بایگانی و بازگرداندن محصولات؛ انتخاب تصویر از هفت تصویر فعلی؛ قیمت صحیح با واحد تومان؛ وضعیت موجود/ناموجود مستقل از نمایش/بایگانی.
- ایجاد، ویرایش، ترتیب و حذف دستهٔ بدون محصول؛ فیلتر «همه» صرفاً در رابط است.
- مدیریت رزروها، فیلتر تاریخ و وضعیت، جزئیات و تاریخچه، تأیید، رد و لغو مدیریتی.
- مدیریت ظرفیت هر ساعت و باز/بسته بودن آن؛ ظرفیت کمتر از مجموع رزروهای فعال قابل ذخیره نیست.
- تنظیم نشانی، تلفن اختیاری، ساعات نمایشی، اینستاگرام و الگوی رزرو. زمان‌ها به وقت تهران هستند. تغییر الگو روی ساعت‌های ایجادنشده اثر می‌گذارد؛ ساعت‌های موجود از بخش ظرفیت ویرایش شوند.
- مدیریت حساب‌های `admin` و `staff`؛ نماینده به منو، دسته، ظرفیت و رزرو دسترسی دارد، ولی تنظیمات، حساب‌ها و گزارش مدیر برای او ممنوع‌اند.
- دریافت QR منو از بالای پنل؛ مقصد QR برابر ریشهٔ `APP_ORIGIN` است.

منو و لندینگ از DB می‌خوانند. ویرایش مدیر به build جدید نیاز ندارد؛ صفحهٔ باز هر ۳۰ ثانیه در حالت visible و هنگام بازگشت focus تازه می‌شود. خطای دریافت به‌روزرسانی، نگه‌داشتن آخرین داده را صریحاً اعلام می‌کند؛ در ورود اولیه، خطای DB با داده ساختگی پنهان نمی‌شود.

## داده آزمایشی و رزرو

seed همان هفت محصول فعلی و سه دسته را درج می‌کند. قیمت‌ها از hash شناسه در محدودهٔ ساختگی ۳۵۰ تا ۶۹۰ هزار تومان ساخته می‌شوند؛ قیمت واقعی رستوران نیستند. seed درج‌محور است: اجرای دوباره رکورد جدید تکراری نمی‌سازد و ویرایش‌های مدیر را برنمی‌گرداند. رکوردهای تست مرورگر نام تست دارند؛ رزروهای مرورگر تست لغو می‌شوند و محصولات تست بایگانی می‌شوند.

تنظیم اولیه: ظرفیت ۲۰ نفر، گروه ۱ تا ۸ نفر، افق ۳۰ روز، ساعت‌های ۱۸، ۱۹:۳۰، ۲۱ و ۲۲:۳۰ و مدت حضور ۹۰ دقیقه. این اعداد از تنظیمات پنل قابل تغییرند. ساعت آخر تا نیمه‌شب روز بعد ادامه دارد. بازه‌ها هنگام نیاز از الگو ایجاد می‌شوند و همپوشانی ندارند.

هر دو وضعیت Pending و Confirmed ظرفیت مصرف می‌کنند. تأیید ظرفیت را دوباره کم نمی‌کند؛ رد و لغو آن را آزاد می‌کنند. لغو مشتری تا فاصلهٔ دقیقاً ۳۰ دقیقه از شروع مجاز است؛ ساعت سرور مرجع است. Pending انقضای خودکار ندارد و باید در پنل بررسی شود.

مالکیت مشتری با cookie محرمانه و HttpOnly در همین مرورگر مشخص می‌شود؛ فقط hash آن کنار رزرو ذخیره می‌شود. شماره موبایل و کد پیگیری به‌تنهایی مجوز دسترسی نیستند. پاک‌کردن cookie، حالت خصوصی جدید یا دستگاه دیگر دسترسی خودکار به رزروهای قبلی نمی‌دهد. سیستم SMS و احراز موبایل در این فاز وجود ندارند. اطلاعات localStorage دموی قدیمی خودکار به DB منتقل نمی‌شوند. بازخورد همچنان دموی محلی مرورگر با برچسب صریح است.

این محیط به رستوران واقعی متصل نیست. رزروهای ثبت‌شده آزمایشی‌اند.

## تست و اجرای نسخهٔ production محلی

```powershell
pnpm exec tsc --noEmit
pnpm lint
pnpm test
pnpm test:db
pnpm db:compat
pnpm test:compat
pnpm build
pnpm start
```

پیش از `pnpm build` سرور standalone قبلی را متوقف کنید؛ در ویندوز فایل‌های آن هنگام اجرا قفل می‌شوند. `start` فایل محیط محلی را می‌خواند. `dev` و `start` را هم‌زمان روی یک پورت اجرا نکنید.

پس از اجرای سرور روی localhost:3000:

```powershell
pnpm test:e2e
node scripts/smoke-standalone.mjs http://localhost:3000
```

Playwright از Chrome نصب‌شده استفاده می‌کند. تست DB یک دیتابیس موقت روی loopback می‌سازد و در پایان فقط همان دیتابیس را حذف می‌کند. تست روی URL راه دور اجرا نمی‌شود. کانتینر profile `compatibility` نسخهٔ دقیق PostgreSQL 10.23 را روی `127.0.0.1:55433` اجرا می‌کند و volume مستقل دارد. دستور `test:compat` همان suite را روی دیتابیس موقت این سرور اجرا می‌کند.

suite دیتابیس شامل ظرفیت هم‌زمان، retry، مالکیت، race تأیید/لغو، مرز لغو، نقش‌ها، ابطال نشست، حفظ ویرایش seed و محدودیت درخواست است. تست مرورگر شامل گردش مشتری/مدیر، ویرایش قیمت، CRUD، نقش نماینده و لغو دسترسی است.

## پشتیبان و بازیابی

```powershell
pnpm db:backup
pnpm db:verify-restore
```

پشتیبان‌ها در `tmp/backups` و خارج از Git هستند. verify-restore ابتدا از دیتابیس محلی dump می‌گیرد، آن را در یک دیتابیس تازه و موقت restore می‌کند و سپس فقط دیتابیس موقت را حذف می‌کند. این دستور دیتابیس فعلی را جایگزین نمی‌کند و برای هاست نوشته نشده است.

## بسته‌بندی و مرحلهٔ بعد

build، assets عمومی و `.next/static` را در standalone قرار می‌دهد و بستهٔ خصوصی `ops` را با SQL، seed، manifest و اسکریپت‌ها کنار برنامه می‌گذارد. فایل‌های محیط از خروجی standalone حذف می‌شوند. `ops` عمومی نیست و وابستگی pg را از node_modules همان standalone می‌گیرد. PDFها در `docs/internal` و `output/pdf` هستند و هیچ‌کدام زیر public نیستند.

خروجی ویندوز فقط برای تست محلی است. در مرحلهٔ انتقال، با تأیید کاربر build Linux در WSL، بررسی read-only هاست، backup، migration/seed و restart Passenger به‌ترتیب انجام می‌شوند. اکنون هیچ فرمانی روی هاست اجرا نشده است.

برای تست با موبایل داخل شبکه، آدرس localhost در گوشی به خود گوشی اشاره می‌کند. بعد از انتخاب IP لپ‌تاپ، `APP_ORIGIN` و `NEXTAUTH_URL` باید با آدرس قابل دسترسی یکسان شوند و سرور دوباره اجرا شود. دیتابیس همچنان روی loopback می‌ماند. QR فعلی تا وقتی origin برابر localhost است برای مرورگر همین لپ‌تاپ است.
